The semantic model

A star schema: Orders and Order Items are the facts; Calendar, Customers, Products and Sellers are dimensions. Lines run from the one side (1) to the many side (*); the arrow is the filter direction. Order Items filters Orders both ways, so a product slicer can reach order-level measures. Hidden columns are in grey italics.

19 DAX measures

All on the Orders table, in display folders. Implicit measures are switched off, so every number in the report comes from one of these.

A report written as code

A .pbip project is plain text, so it can be reviewed, diffed and tested like any other code. Nothing here was clicked together: tools/generate.py writes every file from one readable spec.

  1. Schema-valid. Every report file is validated against Microsoft's published JSON schemas for PBIR, fetched from github.com/microsoft/json-schemas.
  2. No broken fields. Every column and measure a visual uses exists in the model, as the right kind.
  3. No broken DAX references. Every [Measure] and 'Table'[Column] in a measure exists, relationships point at real columns, and sort-by columns are present.
  4. Known answers. tools/expected.py computes every card and chart in pandas with the model's filter rules. After a refresh, Power BI should show the same numbers; they also match the dbt marts (6.8% late, 4.29 against 2.27 stars).
  5. On every push. GitHub Actions regenerates the project from the spec, flags any drift from the committed files, and runs the checks.
